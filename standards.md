# Project Standards and Code of Conduct

This repository uses a simple but strict standard for code quality and team behavior.

## Coding Standards

1. Use descriptive names for variables, functions, and files.
2. Add docstrings and comments when logic is not obvious.
3. Keep functions small and focused on one task.
4. Use type hints and validate inputs.
5. Handle errors explicitly; avoid broad except blocks.
6. Follow formatting and linting rules consistently.
7. Avoid magic numbers and hard-coded secrets.
8. Write clear, readable code that other contributors can maintain.

## Code of Conduct

- Be respectful and professional.
- Keep discussions constructive and inclusive.
- Give feedback without attacking people.
- Help maintain a safe and welcoming environment.
- Delegate work with clarity and accountability.

## Review Rule

All code should be reviewed against these standards before merge.

> This repository includes a deliberately non-compliant example to demonstrate what should not be done.
